# Learning Agent - Saarthi AI

> Owner: Ajay Kumar Prasad | Domain: Learning

## 1. What This Agent Does

The Learning Agent manages the user's learning workflow end-to-end:

- Tracks learning resources (book/course/article/video/podcast)
- Schedules study sessions using Calendar MCP
- Logs and retrieves study notes using Notes MCP
- Tracks weekly study hours and daily streaks
- Creates and tracks study goals
- Runs skill-gap analysis for target roles
- Handles flashcards with SM-2 spaced repetition
- Builds structured learning paths
- Generates recommendation context for the model
- Supports deterministic multi-step role orchestration for intents like:
  - "I want to become a Data Engineer"

## 3. Runtime Architecture

### Layering

- API layer: `main.py`
- Agent layer: `agents/learning_agent.py`
- Tool integration layer: `tools/learning_tools.py`
- Data layer: `db/learning_db.py`
- Contract layer: `db/schemas.py`

### Separation rule used now

- Agent calls DB helper functions and MCP wrappers
- Agent no longer opens direct DB connections for learning path creation
- Ownership checks for sensitive writes are enforced in DB layer

## 4. Request Flows

### A) Standard natural-language flow

1. `POST /learning/chat` -> `run_learning_agent(message, user_id)`
2. ADK Runner executes `learning_agent` with Gemini 2.0 Flash
3. Model chooses among 13 tools from tool docstrings
4. Tool returns structured JSON string
5. `run_learning_agent` validates/parses model output into `AgentResponse`
6. If model output is invalid JSON, fallback returns:
   - `status = partial`
   - safe `summary`
   - `data.raw_text`

### B) Deterministic role-goal orchestration (new)

For messages containing role intent (`become`, `roadmap`, `learning path`) and a recognized role:

1. `tool_analyze_skill_gap`
2. `tool_recommend_resources`
3. `tool_create_learning_path(action='create')`
4. `tool_schedule_study_session` for first path step (tomorrow)

This path returns one unified `AgentResponse` with:

- `actions_taken` chain
- aggregated `conflicts`
- `data`: role, skill_gap, recommendations, learning_path, first_session

## 5. Tool Catalog (13 Tools)

1. `tool_get_learning_status`
   - Aggregates in-progress resources, upcoming sessions, active goals, weekly hours, streak

2. `tool_add_learning_resource`
   - Validates `resource_type` against:
     - `book|course|article|video|podcast`

3. `tool_update_progress`
   - Validates `progress_pct` in `[0,100]`
   - Validates non-negative `current_page`

4. `tool_schedule_study_session`
   - Validates required inputs and date
   - Blocks past-date scheduling
   - Creates calendar event then DB row
   - If DB save fails, attempts calendar rollback via `delete_calendar_event`

5. `tool_log_study_note`
   - Validates non-empty `note_content`

6. `tool_get_notes`
   - Gets notes from Notes MCP with optional resource filter

7. `tool_mark_session_done`
   - Marks study session complete for user-owned session only

8. `tool_query_learning_history`
   - Uses `query_learning_history_safe`
   - Blocks unsafe or non-user-scoped SQL generated by NL-to-SQL

9. `tool_create_study_goal`
   - Validates required fields and positive weekly target

10. `tool_analyze_skill_gap`
   - Validates role
   - Returns missing required/recommended skills and readiness

11. `tool_schedule_flashcard_review`
   - `action='due'`: due cards + stats
   - `action='create'`: validates required fields
   - `action='review'`: validates `quality` in `[0,5]`

12. `tool_recommend_resources`
   - Builds recommendation context from learning data
   - Optionally includes computed skill gap from role keyword

13. `tool_create_learning_path`
   - `action='create'`: path + ordered steps
   - `action='view'`: one/all paths
   - `action='update_step'`: validates status and ownership

## 9. AgentResponse Contract (Authoritative)

From `db/schemas.py`:

```python
class AgentResponse(BaseModel):
    agent: str
    status: AgentStatus  # ok | error | partial
    summary: str
    conflicts: list[str]
    actions_taken: list[str]
    data: dict | None
```

`run_learning_agent` always returns `AgentResponse` even on failures.

## 13. Known Behavior Notes

- Calendar event payload timezone is currently set to `Asia/Kolkata`.
- `query_learning_history_safe` may reject valid SQL if generated SQL omits explicit `user_id` text.
- ADK imports have local fallback stubs so unit tests can run without `google-adk` installed.
